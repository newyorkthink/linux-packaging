# 从云端同步并覆盖本地仓库

## 用途与影响

入口：[sync_from_remote.sh](./sync_from_remote.sh)。适用于通过 `git clone` 检出的 Linux 仓库，从远端拉取最新提交，并在本地对齐当前分支。

常见用法如下。

- 云端已有新提交（例如其他工具在云端直接修改并推送），本地落后。
- 本地工作区出现不需要的未提交改动、未跟踪文件或本地未推送提交，希望直接丢弃并以云端最新提交为准。
- 云端撤回了提交，本地分支还保留旧历史，工作区里还有要继续保留的文件改动。使用 `--keep-local` 将本地分支对齐到云端。

默认同步和强制覆盖按以下顺序处理。

- 先联网执行 `git fetch` 拉取当前分支唯一上游的最新快照；网络或认证失败时直接退出，不清空本地文件。
- 如果本地干净且仅落后于云端，直接快进更新到云端提交。
- 如果本地存在未提交改动、未跟踪文件或未推送提交：默认交互模式先打印清单并要求输入 `y` 确认；显式传入 `-y` 或 `--force` 时直接执行 `git reset --hard <云端提交>` 和 `git clean -fd`，丢弃本地改动、未推送提交引用与未跟踪文件/目录。
- 默认保留 `.gitignore` 忽略的文件，不执行 `git clean -fdx`；不强推远端、不切分支、不修改远端历史。

## 运行条件

- Bash 4.4 或更新版本、Git 2.31 或更新版本、GNU `readlink` 和 `dirname`。
- 脚本位于已有 Git 工作区内，当前处于普通分支（非 detached HEAD），且该分支配置了唯一远端上游与唯一拉取地址。
- 仓库没有未完成的 merge、rebase、cherry-pick、revert、bisect、合并冲突或稀疏检出状态。
- 沿用当前环境已配置好的 Git/SSH 认证，禁用终端交互登录提示，不在脚本内保存凭据。
- 不能设置 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_COMMON_DIR`、`GIT_INDEX_FILE`、`GIT_OBJECT_DIRECTORY`、`GIT_ALTERNATE_OBJECT_DIRECTORIES`、`GIT_NAMESPACE` 等重定向环境变量。

## 使用方法

以下命令在 Linux 终端的仓库根目录运行（也可从任意目录通过脚本完整路径调用，始终作用于脚本自身所属仓库）：

```bash
# 查看脚本帮助，不访问仓库或网络
./Scripts/sync/sync_from_remote.sh --help

# 只读拉取云端快照，预览将被覆盖的改动、提交和未跟踪内容
./Scripts/sync/sync_from_remote.sh --preview

# 同步到云端最新提交（本地干净时直接快进；有待丢弃内容时先列清单并提示确认）
./Scripts/sync/sync_from_remote.sh

# 跳过交互确认，直接以云端最新提交覆盖本地分支并清理未跟踪文件
./Scripts/sync/sync_from_remote.sh -y
```

### 保留本地改动并同步

先预览本地和云端的完整提交号，以及将移出当前本地分支的提交。预览会更新远端跟踪引用和 `FETCH_HEAD`，保留本地分支、暂存区和工作区。

```bash
# 预览本次同步范围并检查文件冲突
./Scripts/sync/sync_from_remote.sh --preview --keep-local
```

确认预览中的提交范围后，将下面两个占位符按顺序替换为预览显示的本地和云端完整 SHA。

```bash
# 将当前本地分支对齐到已确认的云端提交，保留工作区改动
./Scripts/sync/sync_from_remote.sh --keep-local '<本地完整SHA>' '<云端完整SHA>'
```

脚本会重新拉取并核对两个提交号，保留未暂存的改动、未跟踪文件和忽略文件。遇到暂存改动、路径冲突或提交号变化时，脚本会停止。运行期间暂停其他 Git 操作和文件编辑。该模式只更新本地仓库。

## 参数说明

| 参数 | 行为 |
| --- | --- |
| 无参数 | 先拉取云端快照；本地干净时直接快进，有本地改动、未跟踪文件或未推送提交时列出清单并要求交互确认 `[y/N]`；非交互环境会拒绝直接覆盖 |
| `-y`、`--force` | 拉取云端快照后跳过交互提示，直接执行 `git reset --hard` 与 `git clean -fd` 对齐云端 |
| `--preview` | 只读拉取云端快照并输出差异和待清理清单，不改写本地分支、索引或工作区 |
| `--preview --keep-local` | 拉取并预览保留改动的同步范围，检查暂存状态和路径冲突 |
| `--keep-local <本地完整SHA> <云端完整SHA>` | 按预览中的提交号对齐本地分支，保留未暂存的改动、未跟踪文件和忽略文件 |
| `--help`、`-h`、`/help` | 输出用法说明后退出，不访问仓库或网络 |

每次只使用表中的一种调用形式。混用或传入未知参数时返回退出码 `2`。

## 执行结果

| 状态 | 结果 |
| --- | --- |
| 本地与云端一致且工作区干净 | 提示无需覆盖，返回 `0` |
| `--preview` 预览完成 | 打印本地/云端提交号及待覆盖清单，不改任何文件，返回 `0` |
| 本地干净且落后于云端 | 直接快进到云端提交，返回 `0` |
| 本地有改动且确认覆盖（交互 `y` 或 `-y` / `--force`） | 重置分支与已跟踪文件至云端提交、清理未跟踪内容并核对工作区干净，返回 `0` |
| `--keep-local` 且预览一致、文件无冲突 | 对齐并核对本地分支，保留工作区改动，返回 `0` |
| 交互取消、非交互未传 `-y`、或 `fetch` / 校验失败 | 停止执行并保留当前本地现场，返回非零退出码 |

## 复制到其他仓库

将本目录下的 `sync_from_remote.sh` 和 `sync_from_remote.md` 复制到目标仓库的 `Scripts/sync/`，并在目标仓库的同步索引中登记即可。脚本保持 Git 模式 `100755`，说明文档保持 `100644`。脚本不硬编码仓库名、分支名或远端地址，复制后遵循目标仓库自身的认证和授权规则。

实现依据：[Git fetch](https://git-scm.com/docs/git-fetch)、[Git reset](https://git-scm.com/docs/git-reset)、[Git clean](https://git-scm.com/docs/git-clean)。
