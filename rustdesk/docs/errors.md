# RustDesk 报错记录

## 2026-11-03：构建成功后发布前置 API 返回 502

- 来源：[Actions run 41647928327，Build RustDesk](https://github.com/newyorkthink/linux-packaging/actions/runs/41647928327/job/125958179737)。
- 代码提交：`2209288f98fb0df3c142102fd963fd02fff1e984`。
- 发生阶段：官方 AppImage 下载、摘要校验与重新封装已完成；在向 `latest` Release 发布资产时失败。
- 触发条件：上传前的 GitHub API 请求返回非零状态。原流程在 `set -euo pipefail` 下直接退出，这些请求未进入上传重试。
- 影响：构建 Job 标记失败，后续软件版本元数据步骤跳过。现有日志不能证明本次资产已发布，也不能确定是否已执行过旧附件删除。

### 原始报错

下列为本次错误发生处的完整日志片段，保留原 UTC 时间：

```text
2026-11-03T13:52:22.0000838Z gh: Server Error (HTTP 502)
2026-11-03T13:52:22.0001438Z {
2026-11-03T13:52:22.0001757Z   "message": "Server Error"
2026-11-03T13:52:22.0002092Z }
2026-11-03T13:52:22.0082577Z ##[error]Process completed with exit code 1.
```

报错前，appimagetool 已输出 `Success`，并输出生成资产的 SHA-256：

```text
7aa489ef7c5e2dcf4ba216e060d00316b9886f078261d11b26aea46216e5b474
```

### 已核实原因

公共 [build-anylinux Action](../../.github/actions/build-anylinux/action.yml) 原来仅把实际上传放入重试；查询 `latest` Release ID、分页列出附件和删除同名旧附件的 `gh api` 调用，任一失败都会使整个步骤立即退出。

日志没有打印失败请求的 URL，因此不能进一步断定是上述哪一次请求首次返回 502；502 的具体服务端原因尚未查明。本次处理针对已核实的发布重试缺口。

### 处理与状态

- 将三个上传前置 API 操作放入现有的最多 8 次发布尝试，失败后沿用 5、10、15、20、25、30、35 秒退避。
- 查询失败时不使用分页的部分输出；删除失败时跳过上传，下一轮重新查询当前附件列表，避免继续使用可能已删除的旧 ID。
- 所有前置操作成功后才执行原上传命令；180 秒上传超时、精确匹配同名附件、完整分页和失败上限保留。到达上限仍明确失败，不输出发布成功。
- 不改变 RustDesk 的构建脚本、官方 ELF AppRun 或已实测确认的 X11 行为。
- 本轮只读核对日志、YAML 内的发布命令、分支与退出路径及完整 diff；未在用户主机执行测试、构建或复现。提交按现有规则触发正常构建，在线发布结果尚未确认。

后续重新打包时，先核对本记录与当前发布实现；本条发布故障不能作为调整 RustDesk 程序或启动入口的依据。
