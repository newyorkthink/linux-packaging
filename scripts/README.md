# 仓库维护脚本

这里存放在终端中明确调用、可通过参数复用的仓库维护工具。新增工具按用途建子目录，并在本页登记入口、参数、影响和验证方法。

## 目录分工

| 目录 | 用途 |
| --- | --- |
| `scripts/` | 人工或 AI 经授权后调用的仓库维护工具，例如删除指定 Release 附件 |
| `common/` | 应用构建复用的下载、校验、安装、解包和打包入口 |
| `.github/scripts/` | GitHub Actions 调度、构建和发布使用的脚本 |

维护脚本不自动接入构建或定时任务。应用构建继续调用 `common/`；Actions 的既有入口继续放在 `.github/scripts/`。项目归档与恢复的完整步骤见 [归档说明](../archive/README.md)，其他维护入口见 [维护者指南](../docs/maintainer-guide.md)。

## 删除单个 Release 附件

入口：[release/delete_asset.sh](./release/delete_asset.sh)。

需要 Bash、GitHub CLI（`gh`）和 `jq`，以及本机已有的 GitHub.com 认证和目标仓库的发布写权限。脚本检查现有依赖与认证，不安装软件或自动登录。浏览器登录不能代替 `gh` 登录。

在仓库根目录的 Linux 终端执行，先替换所有占位符：

```bash
# 查看参数和退出码说明；此操作不查询、不删除。
bash scripts/release/delete_asset.sh --help

# 使用已核实的仓库、标签和完整附件名，确认后删除指定附件。
bash scripts/release/delete_asset.sh --repo "<所有者>/<仓库>" --tag "<Release 标签>" --asset "<完整附件名>" --yes
```

| 参数 | 要求 |
| --- | --- |
| `--repo` | 必填，格式为 `OWNER/REPO`；固定请求 GitHub.com，不读取当前目录的 Git remote 或 `GH_HOST` 作为目标 |
| `--tag` | 必填，已核实的 Release 标签；本仓库持续发布的产物填写 `latest`，不按“最新发布”自动选择 |
| `--asset` | 必填，区分大小写的完整附件名；按字面精确匹配，含空格等字符时保留引号 |
| `--yes` | 必填，表示已经确认该次删除；缺少时退出，不查询或删除 |
| `--help` | 显示用法后退出，无需依赖或认证 |

未知、重复、缺值、空值参数会被拒绝；标签和附件名也不能以短横线开头或包含控制字符。需要特殊字符时使用正常的 Shell 引用，不把文件名当作命令拼接。

执行过程：

1. 动态读取指定标签的 Release 编号，读取并校验全部附件分页。
2. 按完整名称匹配：没有匹配时，在完整查询成功后报告“无需删除”；多个匹配时停止。
3. 再次确认标签仍指向同一个 Release，只对本次唯一匹配的附件 ID 发出一次删除请求；不保存或复用历史 ID。
4. 重新读取全部附件分页并核对 Release 编号，只有目标名称已不存在，才报告完成。并发重新上传同名附件时复查失败，不继续删除新附件。

脚本只删除指定附件，不删除整个 Release、Tag 或仓库文件，也不改写 `software_versions.json`。归档时的版本条目清理仍按 [现有写锁与独立清理机制](../archive/README.md#独立归档清理)执行。

退出码为 `0` 表示删除后复查通过，或完整查询确认目标原本不存在；参数错误为 `2`，其余失败为非零。删除请求失败、任何分页失败、无效响应、复查失败或 Release 被替换，都不得当成成功。删除请求可能已经生效但复查失败时，保留“未确认”结果，重新完整查询后再判断；不要用 `grep ... || echo gone` 掩盖查询错误。

实现使用 [gh api](https://cli.github.com/manual/gh_api) 和 GitHub 的 [删除 Release 附件 API](https://docs.github.com/en/rest/releases/assets#delete-a-release-asset)，按查询所得 ID 删除，避免按名称二次定位到并发上传的其他附件。

## 公开内容约定

代码、注释和示例使用通用参数或占位符，不写入个人路径、主机名、设备、网络配置、账号配置、令牌或凭据。运行时传入的参数、认证输出、截图和本机日志不能直接作为公共示例提交；只记录完成维护所需的公开结果与验证范围。
