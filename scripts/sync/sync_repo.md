# 同步本地 Git 仓库

## 用途与影响

入口：[sync_repo.sh](./sync_repo.sh)。面向已经通过 `git clone` 建立的 Linux 本地仓库，人和获得当前任务授权的本地 AI 使用同一个入口。

主要操作使用显式的 `pull` 和 `push`，不带参数也可作为 `pull` 的简写。脚本根据自身真实位置找到所属 Git 工作区，不受终端当前目录影响。同步目标来自当前分支的唯一上游，不写死仓库、账号、远端名或分支名。linked worktree 也按各自工作区处理，不要求 `.git` 是目录。

- 拉取先获取指定上游分支的更新，再对固定提交做快进更新；云端新增、修改、删除及执行位变化按 Git 正常同步，无需重新 clone。Git 复用已有对象并传输缺少的对象，不承诺固定传输大小。
- `push` 推送当前分支全部未推送提交，不提交未落盘、未暂存或暂存中的文件。
- `push -m ... -- 文件...` 先提交明确列出的文件，再推送当前分支全部未推送提交。文件清单只限制本次新建提交，不筛除此前已有的提交。

工具不自动 stash、reset、clean、rebase、切换分支、强制推送或安装软件，不默认上传标签和子模块，也不调用来源仓库。冲突和历史分叉会停止，留给当前任务明确处理。

## 运行条件

- Bash 4.4 或更新版本、Git 2.31 或更新版本、GNU `readlink`，以及 `dirname`、`cat`、`mktemp`、`rm` 等常用 Linux 工具。脚本不自行安装或升级。
- 工作区已有提交，当前处于一个明确分支，且已经配置唯一远端上游。通常正常 clone 后的默认分支已经满足；没有上游时停止，不猜测目标，也不自动配置。
- 拉取地址必须唯一。推送还要求解析后的 fetch / push 地址完全相同且唯一；不同的 `pushRemote` / `pushDefault`、多个 push URL 或镜像推送均停止，避免将同一份改动发到另一个目标。HTTPS 和 SSH 均由现有 Git 配置处理；不同协议的两条地址也不自动推断为同一仓库。
- 沿用现有 Git/SSH 认证、提交身份、hooks 和签名设置，不读取或内置令牌，不修改全局配置。HTTPS 终端登录提示被禁用；先由调用者准备好凭据助手、SSH agent 或其他已有认证。
- Git 定位环境变量（如 `GIT_DIR`、`GIT_WORK_TREE`、`GIT_INDEX_FILE`）、detached HEAD、空仓库、稀疏检出、冲突及未完成的 merge / rebase / cherry-pick / revert / bisect 会停止。工具不初始化或递归更新子模块。

运行前保存编辑器内容，并暂停其他 Git 写操作。脚本只能检测已经落盘且 Git 可见的变更，无法检测编辑器尚未保存的缓冲区。符号链接调用仍以脚本真实文件所在仓库为准；把它复制到另一仓库后再执行，才会操作另一仓库。

## 使用方法

脚本首行为 `#!/usr/bin/env bash`，Git 执行模式为 `100755`，可以直接执行，不需要加 `bash`。下例在仓库根目录运行；从其他目录调用时，使用脚本的实际路径即可。进入 `scripts/sync/` 后可用 `./sync_repo.sh pull` 或 `./sync_repo.sh push`；省略 `./` 只在脚本目录已经加入 `PATH` 时有效，脚本不自动修改 `PATH`。

```bash
# 只查看帮助；三种参数均不查询仓库或网络。
./scripts/sync/sync_repo.sh --help
./scripts/sync/sync_repo.sh -h
./scripts/sync/sync_repo.sh /help

# 拉取上游更新。
./scripts/sync/sync_repo.sh pull

# 不带参数也可默认拉取。
./scripts/sync/sync_repo.sh

# 推送已经存在的本地提交。
./scripts/sync/sync_repo.sh push

# 提交两个明确文件，再推送当前分支。
./scripts/sync/sync_repo.sh push -m "<提交说明>" -- "<文件1>" "<文件2>"
```

`-m` 后的文本允许真实换行，提交说明的语言、格式及 CI 标记按目标仓库规则准备；脚本不自行生成事实、增加或删除标记。Git hooks 和正常提交清理规则仍然生效。推送可能触发现有 CI 或发布，不应把“同步脚本”理解为没有远端影响。

本地 AI 已完成获准修改后，提供一次明确文件清单和提交说明即可调用工具；已提交则只用 `push`。首次不熟悉接口时读取帮助，后续直接复用已确认的用法，仍须核对任务授权和提交范围。

## 参数说明

| 参数 | 行为 |
| --- | --- |
| 无参数 | 默认执行 `pull` |
| `pull` | 要求暂存、未暂存和未跟踪内容均无 Git 可见变更，才获取并快进更新 |
| `push` | 获取上游快照后，仅当远端是本地祖先或相同时正常推送已有提交；本地其他未提交改动保留 |
| `push -m 文本 -- 文件...` | `--message` 与 `-m` 等价；先提交文件清单，再推送 |
| `-- 文件...` | 仅用于带提交说明的 push；按仓库根目录解释字面文件路径，不以终端目录为基准 |
| `--help`、`-h`、`/help` | 单独使用或紧跟 `pull` / `push` 时显示帮助，返回 0 |

文件清单必须逐个列出普通文件或文件本身的符号链接，也支持 Git 已跟踪而现在删除的文件。文件名含空格、方括号或短横线时保留 Shell 引号；通配符不会展开成目录内一批文件。重命名时列出旧、新两条路径。拒绝目录、`.`、`..`、绝对路径、重复路径、穿过符号链接目录的路径、Git 元数据及子模块路径。无需 `./` 前缀，例如 `docs/guide.md`。

自动提交模式遇到任何已有暂存内容都会停止，避免混入其他任务或覆盖部分暂存。其他未列明、未暂存的改动保留。本次暂存及提交实际路径会分别复核；hook 引入范围外内容时停止推送，保留本地现场，不擅自回滚。

## 执行结果

| 状态 | 结果 |
| --- | --- |
| 拉取时本地与远端一致 | 报告无需更新，返回 0 |
| 本地落后且无改动 | 快进更新到本次远端快照，返回 0 |
| 拉取时本地领先 | 保留未推送提交，明确提示可执行 push，返回 0；不声称两边已完全一致 |
| 分叉、工作区不满足条件或上游不明确 | 报告原因并返回非零，不自动覆盖或合并 |
| 指定文件无可提交变化 | 返回非零，不生成空提交；已有提交可单独 push |
| 提交成功、推送失败 | 保留本地提交并返回非零；处理认证、网络或远端变化后执行普通 push，不重复 commit |
| fetch / push 查询失败 | 报告 Git 退出码并停止，不把失败当作已同步 |

退出码 `0` 表示帮助、完成或上表明确的无需拉取状态；参数错误为 `2`，其他失败为非零。失败可能留下已经完成的 fetch、暂存或本地提交，不自动清理原有工作。网络操作抑制 URL 和原始错误输出，避免将地址中的认证信息带入日志；具体错误码按现有网络、认证及远端配置排查。

拉取与推送不是跨机器原子操作。获取快照后远端仍可能变化，正常 push 会拒绝不满足快进条件的更新；后续明确处理后再执行。脚本不等待 CI，也不检查应用构建或 Release 结果。

脚本自身也可能在拉取中更新：完整入口在更新前已经解析，当次调用正常结束，新版从下次调用开始使用。每次调用仅创建并清理一个临时工作目录，不清理仓库未跟踪文件。

## 复制到其他仓库

将本目录的 `sync_repo.sh`、`sync_repo.md` 和 `README.md` 原样复制到新仓库的 `scripts/sync/`，并在其维护脚本索引增加入口。脚本保留 `100755`，两份文档保留 `100644`。不要建立指向来源仓库的运行时下载、软链接或同步依赖。

目标仓库继续使用自己的远端、分支、认证、修改授权及保密规则。工具不会同步其他仓库，也不会因被复制就自动执行；AI 只能在当前本地同步任务已获授权时调用。

实现依据：[Git fetch](https://git-scm.com/docs/git-fetch)、[快进更新](https://git-scm.com/docs/git-merge)、[推送目标与 refspec](https://git-scm.com/docs/git-push)、[字面路径参数](https://git-scm.com/docs/git)。
