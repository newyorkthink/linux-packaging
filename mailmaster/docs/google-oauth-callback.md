- 对照 [AUR 配方快照](https://github.com/archlinux/aur/tree/28daf15d8ff9c1efe75dbe2edd1e0673b3ffbe46)所列原始 DEB 与仓库已发布的 AppImage。原始 DEB 的 SHA-256 与配方一致。
- 核对现有授权页面截图、应用日志和浏览器日志。日志记录了 OAuth 窗口启动和 `redirect_uri=http://localhost`，没有找到最终失败地址、接收到授权码或换取令牌的记录。
- 对已有二进制中的回调识别分支做离线调用检查。该检查使用占位授权码和替代回调，不包含真实 Google 登录、授权或令牌交换。

| 检查对象 | 结果 |

| `libmastercore.so` | 原包与 AppImage 的 `.text`、`.rodata` 内容一致。 |

## 回调识别条件

原包和 AppImage 都包含截取 `http://localhost/?code=` 并提取授权码的处理。在 Gmail 的 localhost 回调模式和主框架回调条件下，离线调用得到相同结果：

| 回调地址形式 | 识别分支结果 |
| --- | --- |
| `http://localhost/?code=<占位授权码>&scope=<占位权限>` | 进入授权码处理分支。 |
| `http://localhost/?authuser=<占位值>&code=<占位授权码>` | 未进入授权码处理分支。 |
| `http://localhost/?state=<占位值>&code=<占位授权码>` | 未进入授权码处理分支。 |

表中尖括号内容仅为脱敏占位符，不是可执行的登录地址。

这些结果确认了现有实现对回调地址格式的限制；由于实际失败地址没有被现有日志记录，不能认定本次失败就是参数顺序变化导致，也不能把离线识别通过写成真实授权成功。

## 不能直接套用的处理

- ChatGPT 使用 `codex://connector/oauth_callback`，其协议登记由 [公共 scheme hook](../../common/desktop/write_scheme_hook.sh)处理。大师本次请求使用 HTTP 地址，新增自定义协议登记不能替代其内部回调处理。
- 大师已有内部收码分支，不能仅因地址为 `http://localhost`，就认定必须另外启动 80 端口监听程序；也没有证据表明把回调地址作为 AppImage 启动参数传入就能交给该向导。
- 代理入口标为 mixed 时，不能仅按某个常见端口号认定 HTTP / SOCKS5 选错。界面检测失败也不足以证明代理客户端未运行，或证明检测实现本身已经损坏。
- `Could not bind NETLINK socket`、营销页缺失及推送消息解析异常，与本次授权回跳分别记录和判断。现有材料不足以认定它们造成了此次失败，也不足以断言上游推送协议已经更换。
- 不将“客户端版本旧”“肯定与 AppImage 无关”或“应用专用密码已验证可用”作为本次结论。
