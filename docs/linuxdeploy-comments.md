# linuxdeploy 固定注释标准

本文件是本仓库所有 linuxdeploy 构建脚本及其生成的 AppRun 的唯一注释用语来源，适用于聊天拟稿、修改方案和实际文件。通用原文取自 [Joplin 标准脚本](../joplin/build_joplin.sh)，Qt 原文取自 [XnView MP 脚本](../xnviewmp/build_xnviewmp.sh)；本次核对的源码快照为 [2a0d123](https://github.com/newyorkthink/linux-packaging/tree/2a0d12331c5b71905b414d14be0f3aab674d25e8)。

[Joplin](../joplin/build_joplin.sh) 仍是唯一完整脚本模板，结构、命令、顺序、行距和差异处理继续遵守 [linuxdeploy 规范](../linuxdeploy_projects.md)。本文件固定注释原文，不提供另一套脚本，也不授权增加或删除任何执行步骤。

## 强制复用规则

1. 同一用途只能逐字复制本文件列出的固定注释，包括开头的 `# `、术语、标点和句号。不得改写、缩写、润色、增加前缀或另写同义表述。
2. 注释按实际用途选择。通用注释供各技术栈复用；GTK 和 Qt 注释供采用对应设置的程序复用。依赖包、路径、启动参数和配置取值仍按各程序实际需要确定。
3. 能跨程序复用的注释不得带具体应用名、专属路径或版本号。不得统一添加 `XnView MP 专用：` 或其他应用名前缀，也不得把自动缩放、字体 DPI 等 Qt 设置写成某个应用独有的功能。
4. 问题修复注释必须说明实际问题和处理目的。只有确认符合对应适用条件，并且处理代码已经获准时，才使用本文件的问题修复原文；其他程序不得仅因看到这条注释而照抄处理代码。
5. 每条注释放在对应命令或连续命令块的正上方，不写行尾注释，不把说明集中到脚本末尾。分区标题、位置、缩进和空行继续按标准模板及已获准差异保留。
6. 固定表中没有对应用途时，必须先核实用途、原因和适用范围，提出完整注释原文，经用户明确同意后先补入本文件，再用于对应脚本。禁止绕过本文件临时编写注释。
7. 已确认的通用注释原样保留。不得为了添加原因说明而改写标准原文，不得给简单设置反复增加“保留已确认”等没有补充信息的表述。
8. 本规范不构成批量改写既有脚本的授权。修改注释时，只处理本次获准的注释；已验证的命令、参数、执行顺序和未涉及内容必须原样保留。

## 固定分区标题

按 Joplin 模板中的实际阶段使用，顺序和原文固定；不得为了凑齐标题添加不存在的步骤。

```bash
###### 准备构建目录 ######
###### 准备构建环境 ######
###### 下载打包工具 ######
###### 初始化 AppDir ######
###### 下载并准备应用 ######
###### 准备桌面资源和运行库 ######
###### 准备 AppRun ######
###### 核心打包 ######
###### 整理产物 ######
```

## 已登记的问题处理注释

本表固定已核实的问题处理注释。每条只适用于本行条件；登记注释不表示代码已写入，也不构成向其他应用启用该处理的授权。

| 适用条件和处理原因 | 固定注释原文 |
| --- | --- |
| XnView MP 的桌面入口和图标变量，用于修正官方 desktop 的图标字段，并向 linuxdeploy 提供包内图标路径。 | `# 指定 XnView MP 官方安装包中的桌面入口和图标路径，供图标修正及 linuxdeploy 图标部署使用。` |
| XnView MP 官方 desktop 的 Icon 使用绝对路径，公共封装入口会拒绝该值，因此改为对应图标名称。 | `# XnView MP 官方桌面入口使用绝对图标路径，需改为图标名称才能通过公共封装检查。` |
| 应用自带 Qt 库只在 opt 布局中，linuxdeploy 的 Qt 插件未从 usr/lib 识别到模块；已获准复制自带 XCB 平台库供模块识别。 | `# 复制应用自带的 Qt XCB 平台库，供 Qt 插件识别模块。` |
| XnView MP 包内组件依赖 PulseAudio 和 Wayland，运行日志还显示 Qt 动态加载 PipeWire、VA-API 失败，因此在原收集列表中补入对应库。 | `# XnView MP 的包内组件依赖 PulseAudio、Wayland，Qt 多媒体还会动态加载 PipeWire 和 VA-API，因此一并补入对应运行库。` |
| 在已获准的运行库复制循环中，复制当前选定库及其版本文件。 | `# 复制当前运行库及其版本文件。` |
| 为 XnView MP 补入 PulseAudio 时，同时收集其依赖的 libpulsecommon 配套库。 | `# 为 XnView MP 补入的 PulseAudio 库还依赖 libpulsecommon，因此同时复制该配套库。` |
| 已确认系统 qmake 受应用自带 Qt 库影响，需要通过独立入口隔离系统工具的运行库环境。 | `# 创建独立的 Qt 查询工具入口，避免应用自带运行库影响系统工具。` |
| 在上述已获准的系统工具入口内清除 LD_LIBRARY_PATH。 | `# 清除运行库搜索路径。` |
| 在上述入口中执行真实系统工具并转交参数。 | `# 启动系统工具，并保留传入的命令行参数。` |
| 为上述已获准的工具入口添加执行权限。 | `# 为工具入口添加执行权限。` |
| 当前采用 XCB，并通过应用自带的 IBus 插件和 IBus Portal 接入 Fcitx5；需要明确说明实际输入法连接方式时，使用本行原文，不再以笼统的输入法说明代替。 | `# 使用 XCB 后端，并通过包内 IBus 插件和 IBus Portal 接入 Fcitx5。` |

问题修复注释说明的是具体处理原因，不属于所有程序的默认步骤。相同原因和相同处理方式可以复用同一条原文；原因、处理方式或适用范围不同，必须先按强制复用规则登记新的固定原文。

表中明确写出 XnView MP 的四条注释只用于该应用的对应处理，其他程序不得照抄或仅替换应用名称后使用。其他程序出现相似问题时，必须先核实其实际原因，再按本文件规则登记对应注释；通用、GTK 和 Qt 注释仍保持原文。

具体应用的故障证据、历史处理和验证范围仍记录在应用自己的 README 及专属文档中，不把个案状态写成通用要求。

- 对照适用条件选择本文件的固定原文，同一用途不得另起表述。
- 通用、GTK 和 Qt 注释不加应用名；问题处理注释必须能够说明原因，不用应用名前缀代替原因。
- 未涉及的注释、代码、命令、执行顺序和空行保持原样。
- 本文件未覆盖的用途先登记，禁止在聊天拟稿或实际脚本中自行新增表述。
